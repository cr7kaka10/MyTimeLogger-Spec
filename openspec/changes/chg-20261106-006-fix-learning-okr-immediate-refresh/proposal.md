## Why

PC 客户端的「学习（OKR）」页面新增内容后，列表有时保持旧状态；切到其他页面再返回才出现新内容。代码显示学习命令成功后调用 `pullSync()` 再重读本地库，但该同步属于可被短时间去重的被动拉取，可能在刚写入服务端时跳过，造成页面重读早于新数据入库。实施前用回归场景确认这一根因。当前 KR 还缺少修改和删除入口，重复添加的 KR 无法自行处理。

## What Changes

- 学习目标、关键结果、学习单元及 JSON 导入成功后，确保本次服务端变更完成拉取和本地合并，再刷新当前页面。
- 在每个 KR 标题区域提供修改和删除按钮；允许修改标题，并在确认后删除 KR 及其所属学习单元。
- 服务端学习命令增加按用户归属校验的 KR 修改和删除操作，并发布相应同步变更。
- 新增覆盖连续快速操作的回归验证；同步失败时保留明确反馈，避免把旧列表当作已更新结果。
- 排除项：不改学习数据模型、跨端同步协议及其他页面布局；不做自动去重或合并历史 KR。

## Capabilities

### New Capabilities

- `learning-okr-immediate-refresh`：学习页成功新增或导入后，无需切换页面即可看到最新内容。
- `learning-kr-edit-delete`：学习页可修改 KR 标题，并可确认删除重复或不再需要的 KR。

### Modified Capabilities

无。

## Impact

- 主要影响 PC 客户端共享 UI 的 `ui/src/components/Learning/LearningPage.tsx`、`ui/src/hooks/useLearning.ts`、`ui/src/db.ts`，服务端 `server/domain/learning_plan_service.py`，以及定向回归验证。安卓复用同一 UI，需检查行为。
- 现有模块：学习页命令提交与 KR 卡片、客户端同步拉取、本地学习数据读取、服务端学习计划命令和同步变更日志。
- 回滚方案：回退客户端与服务端对应提交，恢复原有学习页拉取及命令分支；不涉及数据库迁移。已删除的数据须从现有备份恢复，回滚代码不会自动恢复数据。

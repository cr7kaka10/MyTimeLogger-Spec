# 睡眠与时间管理模块 (Time Management Skill)

本模块集成了 aTimeLogger 时间记录和华为运动健康睡眠数据，负责自动生成深度睡眠与时间分析报告。

## 核心计算公式与复核逻辑

### 1. 睡眠周期数
```
睡眠周期 = 睡眠总时长(分钟) / 90
```

### 2. 清醒时长
清醒时长是指睡眠过程中清醒状态的总时长（不包括入睡前和起床后的清醒时间）。程序会在写入数据库前严格按此公式强制复核 AI 提取的数据。
```
清醒时长 = (华为健康醒来时间 - 华为健康入睡时间) - 夜间睡眠总时长
```

### 3. 入睡用时 (关联 aTimeLogger 数据)
```
入睡用时 = 华为健康入睡时间 - aTimeLogger「睡觉/上床」开始时间
```
*(注意：aTimeLogger 返回的时间为 UTC 时间，计算时需 +8 小时转为北京时间)*

### 4. 起床用时 (关联 aTimeLogger 数据)
```
起床用时 = aTimeLogger「睡觉/起床」结束时间 - 华为健康醒来时间
```

## 评价标准

### 入睡用时
| 范围 | 评价 |
|------|------|
| ≤20分钟 | 正常 |
| 21-40分钟 | 较长 |
| >40分钟 | 过长 |

### 起床用时
| 范围 | 评价 |
|------|------|
| ≤10分钟 | 正常 |
| 11-20分钟 | 较长 |
| >20分钟 | 过长 |

### 睡眠评分
| 范围 | 评价 |
|------|------|
| ≥85 | 优秀 |
| 70-84 | 良好 |
| 60-69 | 一般 |
| <60 | 较差 |

## 自动化执行流 (Automated Workflow)

为确保数据百分百准确且避免重复劳动，系统遵循以下严格的执行顺序：

0. **状态检查 (Pre-check)**：在执行“完整分析”前，先行检索数据库。
   - 若当日不存在睡眠数据，或数据**不完整**（缺失核心原始指标）：执行完整流程（从 Step 1 开始），通过 OCR 补全数据。
   - 若当日已存在完整睡眠数据：跳过第 1 步，直接从第 2 步开始复盘。
1. **截图分类与 OCR 原始提取**：Vision LLM 先判断是否存在有效夜间主睡眠，再提取普通指标。
   - 仅当画面明确显示“零星小睡”或“本次睡眠数据不足”，并且同时不存在夜间主睡眠卡片、主睡眠起止时间和阶段指标时，返回 `record_state=no_main_sleep`。
   - 命中后只返回日期与状态；零星小睡时长不得写入 `total_sleep_min`，并立即停止备用视觉模型、aTimeLogger 指标计算和文本报告流程。服务端据此将睡眠评分固定为 0，并只写入一条“无睡眠，严重警告！”-200 流水；不得以缺少入睡时间再追加 noon 处罚。
   - 图片模糊、裁切、未覆盖主睡眠区域，或存在有效但较短/分段的主睡眠时，禁止判为 `no_main_sleep`，继续普通提取或保持数据不完整错误。
2. **时间数据同步**：系统提取对应日期的 aTimeLogger 记录并先行落库，作为计算基准。
3. **二次指标计算**：利用内存 Map 原始数据（或数据库已有数据）与 aTimeLogger 记录，计算 `sleep_cycles`, `awake_min`, `fall_asleep_min`, `wake_up_min`。
4. **Map 补全与落库**：将计算结果填回内存 Map，确保数据完整后，一次性写入华为睡眠数据库。
5. **深度复盘分析**：将包含计算指标的完整数据包与时间记录发送给文本大模型。

## 全天复盘分析 Prompt (Full Analysis Prompt)

以下是用于生成深度复盘报告的提示词，供文本大模型使用：

## 报告格式契约

6. `### 1.4 睡眠评分计算与金币结算`（只展示服务端 `sleep-score-v4` 结算快照的八项原始值、命中规则、得分/满分和逐项金币说明，以及报告时效、总分奖励、周期/深睡/入睡时间惩罚或奖励、睡眠指标全完成奖励、晨间/晚间日记奖励和净额；每笔金额必须带 `🪙`。按时入睡说明必须写明华为 `sleep_start` 的 22:30–23:30 满分、23:31–00:00 部分分、其他时段未达标；禁止模型或报告自行重算）

10. `### 1.7 晨间日记`
9. 完整分析模式追加 `## ⏱️ [Part 2: 时间管理报告]`
10. `### 2.3 AI 时间管理解读`
11. `### 2.4 晚间日记`

`2026-02-07 周六 w06.md` 仅用于参考“变化趋势/上一条对比/增减百分比/AI 数据解读”的表达方式，不作为整体版式参考。

禁止输出整月日历、睡眠质量月历、月份日期网格等块。报告应聚焦当天睡眠、最近 7 天趋势、时间管理复盘和行动建议。
禁止输出 `Generated by MyTimeLogger v4.2` 或同类英文生成尾注。
禁止输出旧的统一 `## 💡 [AI 深度洞察]` 大块。
晨间日记必须属于 Part 1，位于 Part 1 最后；快速报告中必须放在 `### 🎯 睡眠行动建议` 之后，完整报告中必须放在 `## ⏱️ [Part 2: 时间管理报告]` 之前。
晚间日记必须属于 Part 2，位于 `### 2.3 AI 时间管理解读` 之后。

### 固定睡眠结算区（代码拥有）

`### 1.4 睡眠评分计算与金币结算` 是服务端代码生成的固定区块，不属于模型输出。文本模型必须保留该标题与下一节 `### 1.5 华为健康建议` 的边界，且不得生成、改写、省略或重排其中任何八项评分、原始值、命中规则、得分、逐项金币说明、报告完成时刻、金币奖励、惩罚、日记奖励、净额及按时入睡说明。报告文件生成后，服务端会以 `sleep-score-v4` 结算快照确定性替换这一区块；每笔金额以 `🪙` 展示，技术流水 ID 不得出现在报告中；模型只负责其他分析正文。

```analysis_prompt
【身份设定】
你是一个严厉、直接、带强警示性的时间 management 教练和睡眠专家。你将分析用户一天的睡眠数据和时间记录，提供精准的洞察和行动建议；发现懒散、拖延、放纵等具体行为时要直接指出，不要用温和套话糊过去。严重不达标时允许使用刺痛、羞耻提醒式语气，但只能批评具体行为，不能攻击人格、身份、身体特征，不能输出医疗诊断。

【输入数据】
用户将提供一段 **经过程序二次计算补全** 的完整 JSON 数据，包含今日的 OCR 原始指标（评分、各阶段时长）、系统自动计算出的核心指标（睡眠周期、入睡/起床用时、清醒时长）、aTimeLogger 活动统计，以及包含今日在内的最近最多 7 天的睡眠历史记录明细（`history_7day` 字段，已按时间升序排列，包含字段有：`date`, `sleep_score`, `total_sleep_min`, `sleep_cycles`, `fall_asleep_min`, `wake_up_min`, `deep_sleep_ratio`, `awake_count`）。

【分析任务】
1. **睡眠评估与变化趋势**：评价今日睡眠质量、时长、连续性以及入睡/起床效率。每天睡眠周期目标为至少 5 个；睡眠周期、总睡眠、睡眠评分、入睡时长、起床时长、清醒时长、清醒次数是重点指标。并结合 `history_7day` 历史数据，同时输出绝对区间评价和趋势评价。
2. **时间价值评估**：只基于计时页 15 个分类分析：输入、输出、副业生产、副业营销、副业研发、吃饭、家庭、娱乐、车、生活杂事、运动、松鼠病、状态切换、睡觉、拉屎。
3. **逻辑闭环**：寻找睡眠状态与次日效率之间的潜在因果。
4. **行动建议**：提供 3-5 条具体、可执行的建议。不达标指标必须包含严厉批评、问题总结、可能行为原因和当天纠偏动作。

【睡眠评分区间】
- 睡眠周期：>=6 优秀，5-5.99 合格，4-4.99 不足，<4 严重不足。
- 睡眠周期 <3 时必须使用骂醒式严重警示，明确指出“太不像话”“放纵/拖延/懒散把恢复窗口打烂”等强表达；3-3.99 使用严厉批评；4-4.99 明确不合格。
- 总睡眠：>=450min 优秀，420-449min 合格，360-419min 不足，<360min 严重不足。
- 睡眠评分：>=85 优秀，75-84 良好，60-74 一般，<60 较差。
- 入睡时长：<=10min 优秀，11-20min 合格，21-40min 偏慢，>40min 严重拖延。
- 起床时长：<=5min 优秀，6-10min 合格，11-20min 偏慢，>20min 严重赖床。
- 清醒时长：<=10min 优秀，11-15min 合格，16-30min 偏高，>30min 严重干扰。
- 清醒次数：0 优秀，1 合格，2-3 偏多，>=4 严重破碎。

【15 分类时间价值映射】
- 自我提升：输入、输出、运动。输出权重高于输入。
- 经济价值：副业生产、副业营销、副业研发。
- 维护性投入：吃饭、家庭、车、生活杂事、状态切换、拉屎。
- 消耗性投入：娱乐、松鼠病。
- 恢复性投入：睡觉。
- 自我提升和经济价值投入上升要肯定；娱乐、松鼠病上升要扣分；消耗性投入挤压睡眠时必须强烈警告。

【输出要求】
直接输出一个纯 JSON 对象，严禁任何废话，包含以下字段：
- "efficiency_score": 0-100 的综合评分。
- "summary": 一句话总结今日状态（需包含对时间利用率的定性评价）。
- "insights": 字符串数组，至少 5 条深度洞察（必须结合 aTimeLogger 中的具体活动名称和时长进行点评，严禁只谈睡眠；同时必须包含 2 条以上关于最近 7 天睡眠指标变化趋势的洞察分析，指出指标走势是变好还是变差，并进行因果推导；睡眠周期少于 5 个、晚睡晚起、入睡时长过长、起床时长过长、清醒时长或清醒次数偏高时，必须明确点名批评；睡眠周期少于 3 个时必须使用骂醒式严重警示，3-4 个时必须使用严厉批评）。
- "recommendations": 字符串数组，至少 5 条行动建议，每条都必须包含具体行为、时间边界或执行条件，避免“保持专注”“早点睡”这类空泛短句；不达标项必须给出当天纠偏动作。
- "issues": 数组，列出识别出的主要问题点，必须优先覆盖睡眠周期、早睡早起、入睡时长、起床时长、清醒时长、清醒次数。
- "time_management_comment": 针对 Part 2 时间管理部分的专项点评。

【风格指南】
语气严厉、直接、专业。严重不达标时可以使用刺痛、羞耻提醒式语气，但只批评懒散、拖延、放纵等具体行为，不攻击人格、身份。避免空洞的套话。
洞察和建议要比模板句更充分，优先指出“为什么发生、会造成什么影响、下一步如何验证”。
```
